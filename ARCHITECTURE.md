# which-dialect — Architecture & Context

Reference for future sessions/agents. Read this before changing the repo. The user-facing overview is `README.md`; known problems deliberately left for later are in `FUTURE_IMPROVEMENTS.md` (add to it rather than fixing unasked).

## What this is and why

An open-source library for looking up words by **region or dialect**, built to grow into many languages (e.g. Vietnamese *lợn* in the North vs. *heo* in the South; US *truck* vs. UK *lorry*). Languages now: **Vietnamese** (`vi`) and **English** (`en`, also the bridge language), added 2026-09-27. Since 2026-09-30 the owner's focus is **cleaning up Vietnamese first**; more languages are planned (see `FUTURE_IMPROVEMENTS.md`), and the code stays language-general (region groups, `skipFormOf`, translation tables for several languages). The main feature is `createTranslator`: **any language → any language, any dialect → any dialect** (including dialect → dialect across languages, e.g. US English → Southern Vietnamese), translating **meaning by meaning** with the correct part of speech and definition (owner's requests, 2026-09-27).

Renamed twice on 2026-09-27, both before anything was published: `language-dialects-library` → `which-dialect-tool` → **`which-dialect`** (owner's choices). npm packages `which-dialect` (API) and `which-dialect-<lang>` (data); GitHub `nguyen18/which-dialect` (GitHub redirects both old URLs); local folder `~/dev/which-dialect`.

Decisions (2026-09-27, with the owner):
- **Source:** Kaikki.org's JSONL extraction of English Wiktionary (wiktextract). Chosen over the Free Vietnamese Dictionary Project (no dialect tags) and research corpora (sentences, not dictionaries).
- **Region rule (owner's):** senses with no region tag count as used in **every** region. We also keep `regionTagged` so apps can tell confirmed from assumed; the owner agreed.
- **Descriptions are language-general** (owner's request): the README, package descriptions and GitHub description/topics describe a multi-language library, not a Vietnamese one. Since 2026-09-30 (owner): the README also says it's **starting with Vietnamese** and that more languages are planned.
- **Shape:** monorepo; one tiny API package plus one data package per language; data fetched on demand from jsDelivr, never bundled. Generated data is published to npm, not committed to git.
- **Licensing:** code MIT; data CC BY-SA 4.0 (required by Wiktionary's license). Apps that show the data must credit it.

npm workspaces; TypeScript everywhere. Scripts and tests run directly with `node --experimental-strip-types` (Node 22.6+), so they use only erasable TS syntax (`erasableSyntaxOnly`) and `.ts` import extensions. The core package compiles with `tsc` (`rewriteRelativeImportExtensions` turns `./types.ts` into `./types.js`) to `dist/` (ESM + .d.ts).

## Data format (`packages/core/src/types.ts`)

- `data/meta.json`: `LanguageMeta`: lang, name, regions, optional `regionGroups` (group name → member regions), source (URL, retrieved, Last-Modified), license, counts, and `shards` (which files exist).
- `data/words/<xx>.json`: `WordShard`, headword → `StoredEntry[]`.
- `data/en/<xx>.json`: `EnglishShard`, normalized English term → `StoredHit[]`.
- `data/pronouns.json` (only when `meta.pronouns`): `StoredPronounRow[]`, see "Pronoun table".
- `data/picks.json` (only when `meta.picks`): `PickRow[]`, see "Hand-picked words".
- **Stored vs. full form:** files store `StoredSense`/`StoredHit`, where an **untagged sense omits `regions`** (meaning every region, `regionTagged: false`) and empty `labels` are omitted. `toStored()` (build) and `fromStored(item, meta.regions)` (API) convert. Consumers only ever see full `Sense`/`Entry`/`Hit`. This matters most for languages with many regions (listing every region on every untagged sense bloats the data); Vietnamese shrank from 19.6 to 12.2 MB.
- `Sense`: `glosses`, `regions`, `regionTagged`, `labels`, optional `altOf`.
- `Hit`: word, pos, gloss, regions, regionTagged, labels, altOf, `senseIndex`, `senses` (the word's total sense count), `primary`.
- **Sharding:** `shardKey(term, length = 2)` = first `length` letters (English uses 3, recorded as `meta.shardLength`; omitted means 2), lowercased, diacritics stripped (so ñ → n), đ → d, non a–z → `_` (`không` → `kh`, `ở` → `o_`, `ñame` → `na`). Latin-script only: non-Latin languages would all land in `__` and need a script-aware key (a format change → `DATA_VERSION` bump). Two letters (not one) keep files small: typical en shard ≈ 13 kB gzipped, largest ≈ 51 kB (one-letter shards were up to 163 kB). The same function is used to write and read, so **changing it requires a data rebuild and a `DATA_VERSION` bump**.

## Build pipeline (`scripts/build-language.ts`)

1. Download `https://kaikki.org/dictionary/<Name>/kaikki.org-dictionary-<Name>.jsonl` to `.cache/kaikki-<lang>.jsonl` (+ `.info.json` with Last-Modified). Cached; `--refresh` re-downloads.
2. Validate that every `regionGroups` member is in `regions`. Per entry: skip `config.skipPos` and words failing `config.keepWord`. Per sense: skip empty glosses; with `config.skipFormOf`, skip inflection senses (`form-of` tag, unless also `alt-of`); regions from `config.regionsFromTags(tags, raw_tags)`, else all regions with `regionTagged: false`; labels = tags in the `LABELS` allowlist; `altOf` from `alt_of`/`form_of`.
3. English index: terms come from glosses via `termsOf()`: drop `(...)` notes and quotes; if there's a colon, use only the text after the last one ("Negates …: not"); split on `; , /`; normalize (`normalizeEnglish`: lowercase, drop leading to/a/an/the); keep ≤ 4 words of plain letters; also index the bare verb without a trailing particle ("wait for" → "wait"), sharing its position. `primary` = the term is the gloss's first meaning.
4. Variant senses (`altOf`) are indexed under the **target word's** non-variant glosses, preferring the same part of speech (pronoun *tui* → pronoun senses of *tôi*, not its noun "servant").
5. `pos: 'name'` entries are kept in words/ but not in the English index.
6. Writes shards + meta, prints counts and total size.

### Languages

Vietnamese (`languages/vi.ts`): regions Northern/Central/Southern. Tags `Southern`/`Central`/`Northern`; `Central`+`North` = North Central → Central; free-text raw tags mentioning Vietnam/dialect are parsed too. Skips `character`/`romanization` POS and headwords without Latin letters (chữ Hán). Build of 2026-09-27 (Kaikki file dated 2026-09-25): 35,394 entries, 42,419 senses, 1,330 region-tagged (≈3%), ≈29k English terms, 12.2 MB raw across ~617 files (after the stored-form change).

### Large-language trimming (English)

`LanguageConfig` options added for English (1.49M entries, 3.3 GB): `dropTechnical` (drop entries whose every sense has a Wiktionary `topics` field), `formOfPos` (keep inflection senses only for these POS), `keepFormOf(form, lemma, pos)` (English: drop regular forms via `isRegularForm` in `languages/en.ts`; y→i only after a consonant so *said*/*paid* stay), `dropLabels` (obsolete, archaic), `maxSensesPerEntry` (unset for English: no cap, owner's request), `maxGlossLength` (140), `englishIndex: 'regional'` (en/ index of region-tagged senses only, for US ↔ UK etc.), `shardLength: 3`, plus `keepWord` ≤ 2 words and `skipPos` (name, symbol, proverb, …). English regions: 15 countries/areas with groups (North America, British Isles, Oceania, South Asia, Southeast Asia, Africa, Commonwealth); local varieties map to their country. Build of 2026-09-27 (Kaikki file dated 2026-09-25): 594,544 entries, 751,515 senses, 35,393 region-tagged (4.7%), 92.5 MB across 9,598 files, npm tarball 20 MB; largest shard ≈184 kB gzipped; ~25 s, ~1.4 GB memory.

## API (`packages/core/src/index.ts`)

`createDictionary({ lang, baseUrl?, load? })` → `{ meta, lookup, searchEnglish, pronouns }`.
- Default loader: `fetch` from `dataUrl(lang)` = `https://cdn.jsdelivr.net/npm/which-dialect-<lang>@<DATA_VERSION>/data`. `DATA_VERSION` is a jsDelivr range (`'0.1'`).
- Every file loads at most once per dictionary (promise cache); failed loads are evicted for retry. Shards not listed in `meta.shards` aren't requested (no 404s).
- `searchEnglish`: optional `pos` filter (exact POS codes). `region` may be a region or a `regionGroups` name (a group = any of its regions); unknown names throw, listing regions and groups. Then filter out `exclude` labels (default `DEFAULT_EXCLUDED_LABELS`: vulgar, offensive, derogatory, archaic, obsolete, dated, historical, rare, abbreviation) and hits outside the wanted regions; sort by `primary` → tagged for the requested region → label penalty (mild register labels 1, others 2) → `senses` (more = more common) → `senseIndex`; one hit per word; `limit` (10). Unknown region throws.

## Parts of speech (`src/pos.ts`)

`POS_NAMES` (code → readable name + one-line learner explanation), `posName()`, and `COMPATIBLE_POS`/`compatiblePos()`: which target POS can translate a POS from any language (including Vietnamese particle/classifier) (verb → verb/particle/phrase, adj → adj/verb, …), because languages don't align one to one.

## Translator (`src/translate.ts`)

`createTranslator({ dictionary?, baseUrl?(lang), load?(lang) })` → `{ senses(word, { from, fromRegion?, pos? }), translate(word, { from, to, fromRegion?, toRegion?, pos?, meaning?, exclude?, limit? }) }`. Dictionaries are created per language on demand and cached. translate.ts imports from index.ts and index.ts re-exports it at the end (circular import is fine: only used at call time).

**English is the bridge:** every language's glosses are English, so any pair works through them.

1. **Source senses** (`collectSenses`): lookup (+ lowercase); for English (`BASE_FORMS.en = regularBaseForms`) also the regular-form base word with the most senses (*running* → *run*, not *runn*), read after the word's own entries. Variant senses whose first gloss contains "of"/"for" are followed (≤ 2 hops, recording `via`), preferring the same POS; a **region-tagged variant passes its region to the senses it leads to** (*hông* → *không*'s senses, but Southern). Deduped by lemma+pos+first gloss. `fromRegion` (region or group via `resolveRegion`) and `pos` filter them.
2. **Bridge terms** per sense: English source → the lemma first, then `glossTerms` of its first 2 glosses, then its synonyms; other sources → `glossTerms` of the glosses. Max 8.
3. **Candidates:**
   - Non-English target: `searchEnglish(term, { region: toRegion, pos: compatiblePos(source.pos) })`.
   - English target (`englishCandidates`): the term itself if the English dictionary has it with a compatible POS and a sense used in `toRegion`, plus `searchEnglish` on the English **regional** index when `toRegion` is given.
   - Same language (`to === from`): the source sense's **synonyms**, each looked up for its best-fitting sense (prefers a sense that lists the source back, then definition overlap) and kept if used in `toRegion`. Scored from 5 (+3 if tagged for `toRegion`), ahead of English-bridged words. Then a **reverse check**: top-10 candidates whose senses list the source word as a synonym get +4 (*dạ* lists *vâng*).
   - Nothing matched a whole term: the last word of multi-word terms, scored low ("fresh ear of corn" → *corn*).
4. **Scoring** a bridged hit: 3 × definition overlap (content words of the source glosses + `meaning`, minus the term's own words) + term position (2/1/0) + `primary` (1) + tagged for `toRegion` (2) + same POS (0.5) + min(senses, 10) × 0.05 − min(senseIndex, 4) × 0.4 (a word whose main meaning isn't the match) + `registerFit` (polite↔polite / casual↔casual +1, mismatch −2) − 0.5 per slang/literary/… label − rank × 0.1. Best score per word; `limit` per sense. When `to === from` and `toRegion` is set, the source word itself only counts if tagged for the target region.
5. **`allSenses: true`** returns every sense, including ones with no translation (empty `translations`) and ones whose translations repeat another's; used by Language Helper to let users pick any meaning. Default false (the dedupe below applies).
6. **Sense order:** `meaning` overlap × 10, +3 if tagged for `fromRegion`, −1 if all its labels are informal/slang/…, then dictionary order. **Translation scores are deliberately not used to order senses:** tried 2026-09-27 and definition overlap inflated minor senses (*chờ* "letter Ch"). A "main POS = most senses" rule was also tried and reverted (Wiktionary gives *dog* the verb and *bố* the pronoun more senses). Senses whose top-3 translations repeat an earlier sense's are dropped.

**Examples** (added 2026-09-27): `Sense.examples` (`{ text, translation? }`), up to `maxExamples` (2; English 1) per sense, ≤ 160 characters, everyday "example" type before quotations and translated ones first. ~18% of Vietnamese senses have one. Translations get `examples` from their matched sense (looked up for the final `limit` hits only). English `maxSensesPerEntry` raised 6 → 14 (common words list everyday informal senses late: *cool* "fashionable" is sense 9 of 13), then removed entirely at the owner's request; together +4.4 MB. English data is now 130.7 MB (npm tarball 33 MB) (jsDelivr's npm package limit is ~150 MB, so watch it). Region bonus is +2 only when the hit is `primary`, else +0.5 (*bá cháy* is Southern for "awesome", so it shouldn't win *cool* "low temperature").

**Synonyms** (added to the data 2026-09-27): `Sense.synonyms` from Kaikki sense-level `synonyms` (entry-level ones without a sense go to the first sense), max 8. They're Wiktionary's dialect equivalents (vi *ngô* → *bắp*, *lợn* → *heo*; en *lift* ↔ *elevator*). ~10% of Vietnamese senses have them. Sizes after: vi 12.5 MB, en 104.3 MB (en also has the regional index: `englishIndex: 'regional'`, 26,909 terms).

**Subpage titles (2026-09-30):** Wiktionary splits very long pages into subpages and Kaikki uses the subpage title as the word ("i/languages M to Z" for the letter *i*). `readEntries` strips `SUBPAGE` (`/languages X to Y`). Only that one word was affected in vi; none in en.

**Noise fixes (2026-09-27, found generating Language Helper's Cheatsheet):** `glossTerms` drops "etc" (it matched every gloss containing "etc": *there* → nhiệt); senses reached through a spelling variant of a different word (`SPELLING_VIA`: pronunciation spelling, misspelling, …) rank −2 when the word has its own senses (*yeah* ≠ "year"); English bridge terms add the regular base form after the lemma (*thanks* → *thank*); English synonyms are bridge terms only if plain English and score −1 (*thanks* ↛ "cheers" → *dzô*); translations below `MIN_SCORE` (1) are dropped as noise.

**Grammar words and nested senses (2026-09-29, found building contraction parts for Language Helper):**
- `glossTerms` also extracts the phrase after *marks/expresses/indicates/denotes/signals* (`GRAMMAR_PHRASE`): "marks the future tense" (vi *sẽ*) and "Used to express the future tense" (en *will*) both give "future tense". It counts as the gloss's main meaning (position 0) when the gloss's first term is that description itself.
- Bridge terms have a `main` set: the English lemma **and the first term of the definition** get the full main-term bonus (2), so *will* → *sẽ* (via "future tense") beats *thì* (whose gloss "as for …, it is/does/will …" merely mentions "will").
- **Bug fixed:** source senses were de-duplicated by `lemma + pos + glosses[0]`, but Wiktionary nests senses under headings ("As a copulative verb:" → "Used to declare the subject and object identical or equivalent."), so every sense after the first under a heading was dropped. The key now uses all glosses. Headings (glosses ending in ":") are skipped for bridge terms, and `displayGloss(glosses)` returns the specific line for display.
- The translator's internal `searchEnglish` limit went 25 → 100: English "I" has 40+ Vietnamese pronoun candidates, and the dictionary's quick ranking (region-tagged first) cut off *tôi*.
- Dictionary jargon (*speaker, writer, referred, grammatical, subject, object, sentence, word, form, …*) is now in `STOPWORDS`, so it doesn't count as definition overlap (Vietnamese *con* "used when talking to someone older than the speaker" matched English "I" "the speaker or writer" on "speaker").
- Evaluation: tuning unchanged (74/76; first 68/76); held-out first 25 → 26/30.
- `register` option ('casual' | 'neutral' | 'polite') overrides the source sense's register in `registerFit` (Language Helper uses 'casual' for pronoun parts of contractions, since it's about casual chat). "I" → Southern with 'casual': con, tao, **tui**, anh… (tui 3rd; *con* stays first because it's Southern-tagged and very common; picking the right pronoun needs relationship context).

**Translation tables (added 2026-09-27, the owner asked to boost "the word most commonly used for that word in the proper context"):** English Wiktionary lists, per English sense, the usual translation in each language, often with region/register tags. The English build keeps them (`translationLangs` in `languages/en.ts`, currently `['vi']`; add a language's code when adding the language; `Sense.translations: Record<lang, { word, tags? }[]>`, max 12 per language, parenthesized notes stripped, "various" placeholders dropped, only place tags (capitalized) and register tags kept). Coverage: 13,301 English senses have a Vietnamese table. English data is **136.2 MB (2026-09-30) — close to jsDelivr's ~150 MB package limit**; each language's tables add to it, so check the size (or trim, e.g. English examples) when adding languages. In the translator, `tableFor()` gets the table for a source sense: English senses carry it; for other sources, the English sense (from the first 3 bridge terms) whose `translations[from]` lists the source lemma is the same meaning, and its `translations[to]` applies (into English, that English word itself). Each table word gets `TABLE_BONUS` (+4), `TABLE_REGION_BONUS` (+1.5) when its tags name a target region/group, −`TABLE_OTHER_REGION_PENALTY` (2) when they name only other regions. Table words the index missed are added via `tableHit()` (compatible POS first, else any POS: *thanks* (intj) → *cám ơn* (verb)), starting at 3 + commonness + register fit. Results: correct word **first** went 63/76 → 68/76 on the tuning set (held-out unchanged at 25/30; top-3 unchanged); spot checks: computer → *máy tính*; thanks → *cám ơn*. The evaluation now reports top-1 as well as top-3. Tables don't help "you" → Vietnamese (the table says "various"); that needs relationship context. Common words' main senses sometimes have no table in the data (e.g. *pig*).

**Word frequencies (added 2026-09-27, owner's choice of "option 1" for more context-accurate ranking):** `scripts/frequency.ts` loads **wordfreq** lists (`languages/*.ts` `wordfreq`: vi `small` — wordfreq has no large Vietnamese list; en `large`), downloaded to `.cache/wordfreq-<list>_<lang>.msgpack.gz` and decoded with `@msgpack/msgpack` (cBpack: header, then buckets; bucket *i* = frequency 10^(−i/100), Zipf = 9 − i/100). Each entry gets `frequency` (Zipf, one decimal); multi-word terms combine parts as 1/f = Σ 1/fᵢ, minus one Zipf point per extra token (Vietnamese lists are syllables, and *cô nương* otherwise looked as common as *cô*). Hits carry the word's `frequency`; `meta.frequencySource` holds the credit. Coverage: vi 31,981/35,394 entries, en 253,705/594,544. Sizes: vi 15.5 MB, en 135.3 MB.
- **Licensing:** wordfreq's data is CC BY-SA 4.0, and its author asks that it not be converted to formats that drop attribution. We store only one score per word already in our dictionaries, and credit wordfreq and its sources (Google Books Ngrams, Leeds Internet Corpus, Wikipedia, ParaCrawl, OpenSubtitles, SUBTLEX by Brysbaert et al. — "freely available data" — and Twitter statistics) in every README and in meta.json. Keep those credits.
- **Ranking:** `commonness()` = (Zipf − 3.5) × `FREQUENCY_WEIGHT` (1.2); words missing from a language's list count as Zipf 2.5; languages without frequency data keep the old min(senses, 10) × 0.05. The secondary-sense penalty drops from 0.4 to 0.15 per index with frequency data (kinship words list "you" after "I/me"). `searchEnglish` sorts by frequency before sense count.
- **Frequency is per word, not per meaning**, so a common word's slang sense could win a neutral meaning (*cool* the temperature → *chất*, common because it also means "substance"). Fix: `registerFit` now also gives a **neutral** source sense −1.5 against a casual (informal/colloquial/slang/…) target, so *cool* (temperature) → *mát* again and plain "you" demotes blunt *mày*. Polite↔polite / casual↔casual +1 and mismatches −2 are unchanged.
- `meaning` is also matched against each group's top translation's gloss (×5, vs ×10 for the source's own glosses), for targets whose definitions use different words than the source's. It's still word overlap, not semantics: English defines *cool* = "Fashionable; trendy; hip.", so `meaning: 'awesome'` only reaches a translation whose own definition uses that word.
- **The region bonus is deliberately not scaled by frequency.** Tried and reverted: wordfreq is worldwide, so regional words look rare and lost to general words.
- **Effect:** evaluation unchanged (tuning 73/75, held-out 29/30). English "you" → Vietnamese: *anh* moved from 20th to 8th and *chị* from 11th to 14th; the top is now everyday *bạn*, *con*, *mày*, *ông*, but niche Southern-tagged *út*/*tía* still rank above *anh*. Picking the right pronoun needs relationship context (older/younger, male/female, family), the planned next step ("option 2"). A unit test was loosened: frequency legitimately reorders equally correct words (*chất* before *ngầu* for cool = awesome).

## Plain "I" ranking fixes (2026-09-30)

English "I" → Vietnamese ranked *tôi* 27th behind kinship words (*con*, *anh*, *ông*). Causes and fixes, all general:
- **Entry-level translation tables** (build): Kaikki puts some tables on the entry, not a sense (5,219 English entries had such rows for the languages then built, ~2,900 with no sense-level table: *I*, *boy*, *friend*, *answer*, *sea*…), each row labelled with a short meaning ("personal pronoun", "aircraft type"). `attachEntryTranslations` gives each label's rows to the sense whose definitions share the most words with it (`labelWords`: lowercase, >2 letters, trailing *s* dropped, minus a few function words; don't add content words like "person" to that list — it broke *you* → the singular object sense), else the first sense; a sense's own table for a language wins. English data 139.8 → 140.2 MB.
- **English index dedupe bug** (build): hits were deduped by `term + word + pos + senseIndex`, so a word with two entries of one POS (two etymologies) lost the second entry's senses (*ta*'s Central "I/me"). The key is now `term + entryIndex + senseIndex`. All three languages rebuilt.
- **Best sense per word** (translator): `searchEnglish` has `allSenses` (every matching sense of the top `limit` words); the translator uses it so `keep()` scores each word by its best sense (*tôi*'s formal sense instead of its first, informal Northern one). Rank is now per word.
- **Rank penalty capped** at `min(rank, 10) × 0.1`: the dictionary's quick ranking puts every labelled word after unlabelled ones, so formal *tôi* (~30th) lost ~3 points for a label already scored.
- **`tableHit`** prefers a usable sense whose definition contains a bridge term, across all entries (*ta* → "I/me", not "we; us"); table words tagged only for other regions are no longer looked up when the index didn't find them for the target region (a word tagged for another region can mean something else in the target region).
- **Table register tags** count (`tagFit`) when the dictionary sense has no register label: the table marks *ta*/*tớ* informal and *tao* familiar for "I".
- **Shortened table region tags**: a tag that begins exactly one region's name counts as it (≥ 4 letters): "South" → Vietnamese "Southern".
- **Result:** "I" → mình, tôi, ta, con, anh; Southern → tui, mình, tôi, tao, ta; `register: 'casual'` → ta, tôi, tao, tớ, tui. Kinship words stay in the list (they need the pronoun table's listener). Evaluation: tuning 77/79 (3 new "I" cases, all first), first 71/79; held-out **30/30** (was 29), first 28/30 (was 26) — *bát* now passes. The held-out improvement came from general fixes, not from looking at those cases.

## "want" ranking fix (2026-09-30)

English "want" → Vietnamese ranked *mắc* first (its sense "to want to (go to the bathroom, laugh, etc.); to have the desire to", Central/Southern) above everyday *muốn* ("to want"). Cause: definition overlap excludes the bridge term's own words, so a gloss that is **only** the term ("to want") can never earn overlap, while a wordier one did ("desire", and "have" from the source's "have the presence of"). Fixes, all general (`translate.ts`):

- **Exact equivalent** (`exactGloss`, `EXACT_GLOSS_BONUS` +3, like one overlapping word): a `;`/`,`-separated part of the target gloss equals the bridge term ("to want", "mother; mom", "to wait for" via `TRAILING_PARTICLE`, now exported from `types.ts`). **Main terms only** (the English word itself or the definition's first term): side terms' exact matches are looser ("corn" → "cereal" → *ngũ cốc* came first for Southern corn when all terms counted).
- **Narrowed use** (`narrowed`, −`NARROWED_PENALTY` 1.5): the term followed by a parenthetical that names something the source meaning doesn't (`narrows()`: "(go to the bathroom, laugh, etc.)", "in/at (an outdoor or external location)"). Not narrowing, and not blocking an exact match either: restatements that overlap the source meaning ("ngầu": "cool (awesome; fantastic; great)" for cool = awesome), grammar-only ones ("chờ": "to wait (for)"), and **usage notes** (`USAGE_NOTE`: "used…", "said…", or a verb like "answers a …": "dạ": "yes (answers a question)"). A first version narrowed only example lists ("etc."), which let odd senses through ("và": "some (indefinite quantity greater than one)"). `exactGloss` reads the part after a colon like `glossTerms` ("Used as an answer …: no"), and a question ("yes?") isn't the plain word.
- `have`/`has` added to `STOPWORDS`.
- **Result:** want → muốn first in every region (Southern: muốn, thèm, mắc). Evaluation: tuning 45/45 all first (3 new "want" cases), held-out unchanged (17/17, 16 first).
- **Multi-sentence glosses** (`glossTerms`, `types.ts`): parts are also split at sentence breaks, and cross-references (See…, Compare…, cf., Synonym(s)/Antonym(s)) are skipped. English *get*/*got* "To have. See usage notes." had **no** bridge term ("have. see usage notes" failed the term check), so the "have" meaning gave bắt/đi; it now gives **có**, bắt, phải. Skipping "Compare…" matters: "Compare shall." became *will*'s first (main) term and put *thì* above *sẽ*. `glossTerms` is also used by the build, so the index picks this up at the **next data rebuild** (not rebuilt yet; the published data still has the old index, which only means fewer index terms).
- **"got" is ambiguous:** without context the first group is Wiktionary's first *get* sense, "To obtain" → *được*; the "have" sense (casual "I got two brothers") → *có* is the third group. Callers that know the meaning pass `meaning: 'have'` (→ có), `'receive'` (→ nhận) or `'obtain'` (→ được). `meaning` words now always count (`meaningOverlap`), even stopwords like "have": otherwise `meaning: 'have'` was silently ignored. Removing "have" from `STOPWORDS` instead was tried: *got* → *có* first again, but only through the obligation sense (the accident above), and *mắc* came back for want's "want to see" sense. On `main`, *có* led only by accident: the first group was "Expressing obligation; used with have" (have got to = *phải*) and *có* matched weakly through "have".
- **Wider check:** the top-100 English words (`~/dev/top_100_words.txt`) × no region / Southern / Northern, first sense group, compared with `main`: the top word changed in 16 of 300 queries (after the gloss-split fix below too), all improvements or equivalents (want → muốn; got "obtain" → được, not có; yes → dạ, not phải; feel "touch" → sờ, not lần; to → đến, not với; something → cái gì, not gì); 2nd/3rd picks changed in ~45 more, mostly neutral. Known leftover: in → ngoài 3rd (its parenthetical mentions "location", like the source definition). Use this comparison for future scoring changes: the 45 evaluation cases miss most side effects.

## Inflected forms with their own meanings (2026-09-30)

English *got* has its own entries ("Expressing obligation; used with have.", "Must; have/has (to).", "Have/has.", both colloquial; Singlish "Have; there is") besides being the past of *get*. Its "Have/has." meaning was ranked after all of *get*'s meanings (colloquial −1) and then dropped as a duplicate of *get*'s "To have", so "got" gave *được* ("To obtain") first. Fixes (`translate.ts`, sense order):

- **`formWithBase`**: the word has its own senses and also reaches a base word through an **inflection** (`INFLECTION_VIA`: "simple past of get", "form of run"; not contractions like *kinda* → "kind of", nor spelling variants). Then its own senses get +1, unless they're marginal for reasons other than everyday speech (`EVERYDAY_LABELS`: colloquial, informal; slang/Internet senses keep −1, so *felt* "To thoroughly defeat" (Internet) stays behind *feel*).
- **`CONSTRUCTION`** (−0.5, only among such a form's own senses): a definition needing a following construction ("(to)", "(with …)", "used with", "followed by") is narrower than a standalone one, so "Have/has." comes before "Must; have/has (to).". Applied to all senses at first, it demoted function words' main meanings ("would": "Past tense of will; usually followed by a bare infinitive" → "hoàn cảnh" came first), so it's scoped.
- With `allSenses`, senses with no translations sort last ("Expressing obligation; used with have." finds nothing).
- **Result:** got → **có** (Have/has.), có (Singlish "have; there is"), **phải** (Must), then get's senses; `meaning: 'must'` → phải. *should* (past of *shall*) → **nên** first (was *căng*). *felt*/*saw* unchanged (own entries first: fabric, tool; see FUTURE_IMPROVEMENTS.md "Meaning order"). Top-100 comparison vs the previous commit: only got, should and good's 3rd meaning (*ngoan*) changed. Evaluation: tuning 48/48 all first (3 new cases: got → có, got + must → phải, get → được/lấy/nhận), held-out unchanged.
- **Passive voice** (`PASSIVE`, −`VOICE_MISMATCH_PENALTY` 3, bridged hits): a target sense whose definition says passive/passively, when the source sense doesn't. *get* "To obtain; to acquire" gave *được* ("to obtain, to get (passively)") first, ahead of everyday *lấy* (owner's call, 2026-09-30): *được* led by frequency (+4.2 vs +2.76) and by "obtain" being its first term (+1), but it's common mostly as a helper verb ("được đi", "làm được"). The penalty is sized to offset that. Now get → **lấy**, được, nhận. Side effect (correct): *được*'s passive-marker sense no longer appears for non-passive "be" senses (be/is/was… 2nd and 3rd meanings: là, ở, làm); the passive "be" sense still gives bị, được. The *get* evaluation case now expects *lấy*.
- **List definitions** (`isTermList` in `bridgeTerms`): when the first definition is only a short list of equivalents (every comma/semicolon part a term of ≤ 3 words: "To fetch, bring, take."), all its terms are main terms, not just the first. *get* "To fetch, bring, take" gave hóng, bắt, ra khỏi (found only through the ambiguous "get" itself); now **đưa, lấy**, hóng. *lấy* isn't first because *đưa* ("to bring, to take, to give, to hand") matches two of the three terms and no *lấy* sense says "fetch" (a data gap; the planned picks layer covers it, see FUTURE_IMPROVEMENTS.md). Top-100 comparison: top word changed only for *now* ("Present; current" → hiện tại, was đưa ra); 2nd/3rd picks improved elsewhere (still "Not moving" → im; cool "Unenthusiastic" → hờ hững; just → chính xác). Known noise: *do* "To perform; to execute" → *tử hình* 3rd (execute = put to death; làm still first).
- **Meaning frequency isn't available:** Wiktionary translation-table sizes looked like a signal but tables are often on the wrong meaning (see FUTURE_IMPROVEMENTS.md), so the dictionary's order stays the default.

## Hand-picked words ("picks", added 2026-09-30)

A speaker's first choice for common English meanings, where the ranking puts another word first (*get* "To fetch, bring, take" → *lấy*, not *đưa*). Designed with the owner to scale to many languages (see "Working conventions"):

- **Config:** `LanguageConfig.picks`: `PickRowConfig { word, pos, gloss: RegExp, picks: (string | { word, tags? })[], first?, note? }` in the **target** language's config, keyed by **English meaning** (English headword + part of speech + a definition pattern). One list per language, never per pair. Vietnamese: *get* "fetch" → lấy, mang; *get* "obtain" → lấy.
- **Build** (`scripts/picks.ts`, `writePicks`, called at the end of `build-language.ts` and standalone as `npm run build:picks -- <lang>` so editing picks doesn't need a data rebuild): finds each row's English sense in the **built English data** (skipped with a warning if English isn't built), stores that sense's exact first gloss, checks each word exists in the language, writes `picks.json` (`PickRow { word, pos, gloss, picks: TableTranslation[], first? }`) and sets `meta.picks`. Warns (doesn't fail) for rows matching no sense, several senses (uses the first), or unknown words, like the pronoun table.
- **API:** `dictionary.picks()` (loaded on demand, `[]` without `meta.picks`).
- **Translator:** `englishMeanings(sense, from, bridge)` (factored out of `tableFor`, unchanged behavior) gives the English meanings of a source sense: an English sense itself, or the English senses whose translation table lists the source word. Rows match by exact word + pos + gloss. Picked words go first in the group, in listed order (`bridge: 'picked'`, score above the top ranked word); with `toRegion`, tagged-for-target picks lead, and picks tagged only for other regions, or untagged picks whose sense isn't used there, are left to the ranking; excluded labels are respected; within one language the source word itself isn't picked unless tagged for the target region. Ranked words follow; `limit` applies to both. A pronoun-table row (listener/about/default) still goes before picks. `first: true` gives the meaning +5 relevance when no `meaning` is given. `picks: false` turns them off. Not applied into English (picks are keyed by English meaning).
- **Review loop** (`npm run picks-sheet -- <lang>`): a CSV (default `.cache/picks-<lang>.csv`) of the top English words (`topWords()` in `frequency.ts`, from wordfreq; or `--words file`) × up to 4 meanings each: English word, pos, meaning, the ranking's top 3 (picks off), Wiktionary table words, current pick, empty `your_pick`. `--apply file.csv` prints config rows (`"heo (Southern) / lợn"` → tagged picks). Top-100 list: 313 meanings, under a second.
- **Evaluation** runs each set with and without picks and breaks results down by target language: tuning 49/49 first with picks, 48/49 without (the new *get* [fetch] case: the ranking alone gives đưa); held-out unchanged.
- **Tests:** fake-data tests for order, `picks: false`, region tags and reaching picks from another language through the English meaning (35 tests).
- **Compatibility:** additive. Old API versions ignore `picks.json`; the new API with old data sees no `meta.picks`. `DATA_VERSION` unchanged. `picks.json` is generated data, so it reaches users when the language's data package is republished.
- **How it scales** (the owner's requirement for every feature):
  1. **Optional per language:** a language without picks uses the ranking alone; adding a language never requires picks.
  2. **One list per language:** keyed by English meaning, so N languages need N lists, not N² pair lists; other languages reach them through the English meaning (`englishMeanings`).
  3. **Lives with the language, not the API:** rows in `languages/<lang>.ts`, data in that language's package (`picks.json`), loaded on demand; the API doesn't grow with languages, and picks are versioned with their data.
  4. **Machine-drafted, speaker-reviewed:** the sheet does the drafting for any language; only reviewing grows with languages, and that's the part that needs a speaker.
  5. **Frequency first:** top 100 English words, then 500 (`--top 500`), 1000.
  6. **Survives data refreshes:** rows match by word + pos + definition pattern, and the build warns per language when one stops matching.
  7. **Measured per language:** `npm run evaluate` with and without picks, broken down by target language.
  8. **Upstream when possible:** Wiktionary's table format, so good picks can go into Wiktionary's translation tables.

## Grammar checker (added 2026-10-01)

The owner asked for a Vietnamese grammar checker living in this repo, designed to scale to other languages; chosen over a sentence translator because it can be rule-based, free, and only speak up when confident (a translator has to be right about everything). `createChecker(options)` (`src/check.ts`; options like the translator's) → `check(text, { lang, region?, listener?, about?, speaker?, rules? })` → `{ text, issues }`. `text` is the input NFC-normalized; issues carry offsets into it, `rule`, `severity` (error / warning / suggestion), `message`, `suggestions` (replacements for the span).

- **Pipeline:** units (`/[\p{L}\p{M}\p{N}'’]+/gu` runs) → sentences (split at `.!?…` and newlines) → words by **longest match** against the dictionary (`dictionary.lookup`, cached per phrase), up to `maxWordUnits` units joined only by spaces ("kết quả" is one word, so its "quả" isn't checked alone) → rules in parallel → sorted by position, then severity.
- **Per-language settings, not code** (the scaling rule): `LanguageConfig.checker: CheckerConfig { units?: 'words' | 'syllables', maxWordUnits?, pronouns?: per pronoun-table column, ambiguousPronouns?, politeEndings? }` → `data/checker.json` (`meta.checker`); with `units: 'syllables'` the build also writes `data/syllables.json`, every headword syllable → wordfreq Zipf (0 unknown) (`meta.syllables`). Vietnamese: 7,095 syllables, 80 kB. API: `dictionary.checker()` / `dictionary.syllables()` (`{}` without). Pronoun-table rows can be marked `respect` (vi: parent, parents-age, grandparents-age, teacher).
- **Rules** (all language-general; each is skipped when the language lacks its data, so a language without checker settings still gets `dialect`):
  - `spelling` (syllable languages): a unit not in the syllable list → candidates with the same letters without accents (`plain`: NFD, drop marks, đ→d), by frequency, max 3, case kept. Plain-letter units with no candidate are skipped (names, foreign words: "email"); accented non-syllables are `error`, missing accents `warning`. Units inside a known word aren't checked.
  - `dialect`: a word is regional when its **main meaning** (first sense of its first entry) is region-tagged (and not tagged for every region). Checked: lợn/ngô/thìa/quả/nhé (Northern), heo/muỗng/tui/nha (Central, Southern); not: má, hông, bắp (main meaning untagged: cheek, hip, blossom), which is deliberate (silent rather than wrong). With `region`: words not used there → `warning`, suggestions from the translator within the language (`toRegion`, same pos, limit 3; the message names only the first: "heo", not niche "cúi", "ỉn"). Without: the regions most regional words share are the text's; outliers → `suggestion`; when no region has a majority but words clash ("lợn" + "nha"), every regional word gets a "mixes regions" `suggestion`, no guess.
  - `pronoun-relationship` (needs `listener`/`about` and the pronoun table): a reliable pronoun (`checker.pronouns`) whose column's words in the listener's row (region/speaker-filtered via `dictionary.pronouns`) don't include it → suggestions = those words. `ambiguousPronouns` (vi: bạn, also "friend") → hedged `suggestion` ("If “bạn” means “you” here: …").
  - `pronoun-pair` (no listener): an "I" pronoun and a "you" pronoun with no pronoun-table row containing both (tao + bạn) → suggest the rows' "you" words for that "I".
  - `polite-ending` (listener row `respect`, `checker.politeEndings`): sentences not ending in one → `suggestion`; skipped for exclamations ("Con nhớ má quá!").
- **Vietnamese settings** (`languages/vi.ts`): `units: 'syllables'`, `maxWordUnits: 4`, pronouns self tôi/tui/tớ/tao, selfPlural chúng tôi/ta/mình/tao, tụi tui/tao/mình, addressee mày/bạn, addresseePlural các bạn/chúng mày/tụi mày/quý vị; **left out on purpose**: con (child, classifier: con chó), mình (body, self), nó (it), họ (surname): checking them would cause false alarms. Pronoun matching is on units directly, so pronouns the dictionary doesn't list as one word (tụi mày) are found. `politeEndings: ['ạ']`.
- **Pronoun-table fix found by the checker:** the friend row now includes *tôi* (definition "used when talking to one's friends", tagged Northern), which was a false alarm; in Southern text *tôi* to a friend is still flagged, per the tag. Translation evaluation unchanged (49/49; 48/49 without picks; held-out 17/17).
- **Tests** (`test/check.test.ts`): a fake syllable language exercising every rule (segmentation, accents and case, region with and without `region`, mixed regions, relationship, pairs, polite endings and exclamations, offsets, rules off, unknown listener, a language without checker settings), and real Vietnamese data: the learner-mistake sentence, pairs, Northern muỗng → thìa, mixed regions, plus **13 correct sentences that must come back with no issues** (false alarms make a checker useless; add to this list whenever one is found). ~10 ms per sentence.
- **How it scales:** rules are language-general and read only data; per-language work is the `checker` block in `languages/<lang>.ts` plus data in that language's package; a language without settings degrades to space-separated words + `dialect` (English: US *apartment* in UK text → *flat*). Not yet: languages without spaces (Chinese, Japanese, Thai) need a `units: 'characters'` mode (longest match over characters); see FUTURE_IMPROVEMENTS.md.

## Sentence frames and journal review (added 2026-10-01)

The owner wants learners to write journal entries in Vietnamese, English or a mix ("broken target-language speech"), get the corrected entry under each sentence, and be offered sentence frames. **No LLM** (owner, 2026-10-01): everything is rule-based on the language's data.

**Frames** (`languages/frames.ts`, `scripts/frames.ts`, `src/phrasebook.ts`):
- **Catalog, written once:** `FRAMES: { id, topic, en: string[], slots?: { name: 'noun'|'verb'|'adj' }, clause? }[]` (34: journal, feelings, questions, requests, greetings). `en` alternatives are matched in order, so specific frames go first (want-to before want; ask-want before ask-yes-no). `clause` frames can be part of a sentence ("but it was {quality}").
- **Per language** (`LanguageConfig.frames: { frame, text }[]`, `frameWords: Record<KEY, { meaning, optional?, words: FrameWordPick[] }>`): `text` has content slots (lowercase), pronoun slots (`FRAME_PRONOUNS`: I, YOU, WE (exclusive), WE_INCL, YOU_PL, HE_SHE, THEY → pronoun-table columns) and frame word slots (uppercase). Frame words are gloss picks (region/labels from the sense) or overrides with a note, plus `when: 'respect'` (used only when the listener's row has `respect`). Build → `data/frames.json` (`StoredFramesData { frames: FrameData[], words }`, catalog fields copied in so the API needs no catalog), `meta.frames`; warns for unknown frames, unknown or unused slots, and unmatched definitions. Vietnamese: 34 frames, 13 words from definitions, 3 overrides (*chừng nào*, *hông* ×2: Southern colloquial, untagged in Wiktionary). API `dictionary.frames()`.
- **Choosing a word** (`choose`): keep choices used in the region (untagged = all), `when: 'respect'` only for respect rows, casual labels (colloquial, informal, familiar, slang, Internet) only with `register: 'casual'` (then first); then region-tagged-for-target first, then config order. Pronouns: the listener's row (else the default row), column filtered by `inclusive`, same choice rules.
- **`createPhrasebook(options)`** (options like the translator's, or share one via `translator`): `frames({ lang, region?, listener?, speaker?, register?, topic? })` (content slots open as `{name}`), `render(id, { …, slots })` (slot values: English → translator `en → lang` with the slot's pos, region, register, limit 1, leading the/a/an/some dropped; or `{ text }`), `match(english)` (normalized lowercase, curly quotes, final punctuation dropped; each `en` template → regex with `(.+?)` slots), `matchFrames(sentence)`. Results are `FilledFrame { id, topic, en, text, parts: FramePart[] (kind fixed/word/pronoun/content, why, regions, from, untranslated), slots, complete }`. Text tidy-up: single spaces, none before punctuation or for empty slots; first letter capitalized unless `clause`. Unknown ids throw, listing valid ones.
- **`matchFrames`** (checking a sentence in the language against frames): each frame text → regex: fixed words (flexible spaces), content `(.+?)`, frame words = alternation of all choices **and their accent-less forms**, pronoun slots = every word of that column in every row (all regions, `exclude: []`) and accent-less forms; question frames only match questions. Frame word slots are optional when the frame has fixed words (so a missing required word is caught: *Bạn có đi?* → *không*); frames with **neither fixed words nor frame words** (`{I} {quality}.`) are skipped, as they'd match almost anything. Changes: accent-less word in a slot → accented (*Toi* → *Tôi*); frame word not allowed for the region/register → the chosen word (*mô* in Southern → *đâu*); missing required (non-optional) frame word → added; pronoun not fitting the listener → the listener's word, **only when `listener` is given** (in a journal *Má* may be who you write about). POLITE and SOFT are optional, so never added (the checker's polite-ending hint covers *ạ*).

**Journal review** (`src/review.ts`, `createReviewer().review(entry, { lang, base = 'en', region?, listener?, speaker?, register? })`):
1. Sentences (`text.ts`), then each unit's language: target 'exact' (a syllable as written, or accented) / 'accents' (a syllable only with accents added); base = the translator's `senses(u, { from: base })` (so inflected forms count). exact & base → ambiguous; exact only → target; base (and not exact) → base (*but* is English, not *bút*); accents only → target (*khong*); neither → ambiguous. Ambiguous units take the nearest decided neighbor's language (left first), else the target.
2. Base parts: whole sentence (with its punctuation) or part → `phrasebook.match`; a `complete` match replaces it (lower-cased first letter mid-sentence) → change `kind: 'frame'`, why `Sentence frame “<catalog English>”`. (Since the spellchecker change below, other base words are left to the checker's `foreign-word`; before it, parts ≤ 3 units were translated here and longer ones listed as `unchecked`.)
3. The draft entry (all replacements) → `checker.check` on the **whole entry** (consistency across sentences); per sentence, errors/warnings with suggestions are applied right to left (first suggestion; overlaps skipped) → changes with the checker rule as `kind`; suggestions → `hints`.
4. `phrasebook.matchFrames(corrected)` → frames listed (`{ id, en, text }`, English template and pattern for the settings). Since the spellchecker change below, frames **don't change** the sentence (before it, the first match with changes was applied: missing *không*, *Toi* → *Tôi*).
Output `Review { text, corrected, sentences: ReviewSentence[] }`. ~50–150 ms per entry.

**Checker rule added:** `pronoun-consistency`: a reliable pronoun differing from the first one used for the same column in the text → warning, suggestion = the first (*tui* after *tôi*); hedged when either is ambiguous.

**Tests** (`test/frames.test.ts`): fake-data phrasebook (region words, casual register, listener and respect, frame listing, matchFrames: missing word, other region, accents, listener-only pronoun changes, unknown id, a language without frames) and real data (render by region/listener, English match, clause, no match), journal review (the mixed example entry, frame grammar + accents + unchecked, **correct entries that must come back unchanged**). 57 tests.

**How it scales:** the catalog is written once; each language adds `frames` + `frameWords` in its config and gets `frames.json` in its package (N lists, not pairs); pronoun slots use each language's pronoun table; a language without frames has none, and review then relies on word translation and the checker. Language detection and review are language-general (two dictionaries; syllable languages get the accent rules).

## Spellchecker by default (2026-10-01)

The owner repurposed the grammar checker as **option 2**: a spellchecker by default, other checks opt-in, and **a correction for every word**: target-language words get their accents, words in the learner's own language (English; the owner: "the target language is Vietnamese and the non-target language is English") get the Vietnamese word. Sentence frames stay (listing, filling, English → frame) but no longer correct sentences.

- **Defaults:** `DEFAULT_CHECK_RULES` = `spelling` + new `foreign-word` on; `dialect`, `pronoun-relationship`, `pronoun-pair`, `pronoun-consistency`, `polite-ending` off. `rules` overrides per rule (`opts.rules?.[r] ?? DEFAULT_CHECK_RULES[r]`). **Behavior change** for callers of 0.2.0/0.3.0 (all rules were on): pass the rules you want. New options `base` (default `'en'`; none when it equals `lang`) and `register`. `CheckResult.parts`: the text split by language.
- **Language marking** moved to `src/detect.ts` (`markLanguages(units, { lang, base, target, baseDictionary, translator })`), shared by the checker and the review. Unit classes: target 'exact' (syllable as written or accented) / 'accents' (a syllable only with accents added); base = `translator.senses(u, { from: base })` non-empty. exact & base → ambiguous; exact → target; base (not exact) → base (*but*, not *bút*); accents → target (*khong*); neither → ambiguous. Units both know go by **frequency first** (`baseDictionary.lookup` frequency vs the syllable's): ≥ `TARGET_MARGIN` (1) Zipf more common in the target → target (*em* 6.1 vs 4.6, *di* 5.7 vs 4.3, *tui*: English Wiktionary has rare "em", "di", "tui"); ≥ `BASE_MARGIN` (2) more common in the base → base (*the*). Close calls (*an* 5.9/6.5, *to*, *do*, *me*) and units neither knows: neighbors when they agree, target when they disagree, none decided → target. Fixed 2026-10-01 after *hello em di shopping…* marked *em di* English (both neighbors English; neighbors used to come first).
- **`foreign-word`** (`MAX_FOREIGN_UNITS` 3): per sentence, runs of base units joined by spaces; at each position the longest phrase (k ≥ 2 only if the base dictionary knows it) that the translator translates (`from: base`, `toRegion`, `register`, `listener`, limit 3), falling back to shorter, down to single words, which always give an issue (no suggestions when nothing translates → the review's `unchecked`). Single words in `CheckerConfig.leaveOut` (vi: the, a, an: no articles) → suggestion `''` (leave out). Severity `error`; suggestions keep a capital at sentence start. Spelling and dialect skip base units.
- **`spelling`, rare plain-letter words:** besides non-syllables, a plain-letter syllable that is valid gets suggestions when an accented form is ≥ `ACCENTS_GAP` (1.5 Zipf) more common (*toi* 3.8 → *tôi* 6.5, *hom*, *nao*, *co*, *ve*), or ≥ `ACCENTS_GAP_UNACCENTED_TEXT` (0.2) in a sentence **typed without accents** (≥ 50% of its target units plain and a missing-accents error, or 3+ units with no accent at all; 50% rather than more because frames filled in by the review add accented words): *an* 5.9 → *ăn* 6.1, *di* → *đi*; not *con* 6.3 vs *còn* 6.4. Skipped: units inside a known multi-syllable word, capitalized units mid-sentence (names), and the language's listed pronouns (`checker.pronouns`; *tui* is always unaccented, and *túi* "bag" is more common). Severity `warning`.
- **Picks for small grammar words** (vi, so word-by-word translation reads right): *but* (conj "However, although…", table: nhưng) → nhưng; *be* (copula "identical or equivalent") → là; *very* → rất; *of* (possession) → của; each `first: true`. Without them: but → song (literary), is → bị (passive), of → bằng. 6 English meanings, 7 words; translation evaluation unchanged.
- **Review:** the review's own word translation and frame fixes are gone; an English part that doesn't match a frame as a whole is searched for a **clause frame ending it**, longest first ("the ice cream but it was expensive" → *kem nhưng mắc quá*: the clause by its frame, the rest word by word; `FilledFrame.clause`). Only spans ending with the part: allowing any inner span matched "but it was very" with quality "very" → *thực*, leaving "expensive"; `checks` passes opt-in rules to the checker; leaving a word out tidies spaces. ## Words of several syllables: segment, variants, accents by neighbors (2026-10-01)

Asked from Language Helper's journal, where hovering a word offered other accents one syllable at a time, so *hôm nay* ("today") was *hôm* + *nay*, and a learner's *hom nay* was corrected to *Hôm này* ("this"). The fix belongs in the library: it knows each language's word length and syllables.

- **`dictionary.segment(text)`** exposes `text.ts`'s longest-match `segment` (the checker's), with the checker's `maxWordUnits` (default 3): `WordSegment` `{ text, start, end, entries }`, offsets into the NFC text, punctuation left out, unknown units as words with no entries.
- **`dictionary.variants(word, { limit = 5 })`**: `WordVariant` `{ word, entries, frequency? }`. Each syllable's forms with the same letters (`syllablesByPlain`, most common first: `VARIANT_FORMS_ONE_SYLLABLE` 12 for one syllable, `VARIANT_FORMS_PER_SYLLABLE` 5 per syllable otherwise), combined by `accentCombinations` (combinations of more common forms first, at most `MAX_VARIANT_COMBINATIONS` 64), looked up, kept when the dictionary has them, sorted by the entries' highest Zipf frequency (the syllable's own for one syllable). Every accent variant of a word shares its shard (`shardKey` drops accents), so this loads no extra files. `[]` for languages without a syllable list.
- **`spelling` by neighbors** (before the per-syllable checks): a unit is **doubtful** when it isn't a syllable (with forms it could be) or is a plain-letter syllable with a more common accented form (the same `ACCENTS_GAP` / unaccented-text rule as before). Runs of 2..`maxWordUnits` lone target units joined by spaces that contain a doubtful one are tried, longest first: only the doubtful units vary (`COMPOUND_FORMS_PER_SYLLABLE` 5, at most `COMPOUND_MAX_COMBINATIONS` 64), and the combinations the dictionary has become one `warning` for the whole run, most frequent first (*Hom nay* → *Hôm nay*, *an com* → *ăn cơm*, *Chung toi* → *Chúng tôi*, *hôm nây* → *hôm nay*). Its units then skip the per-syllable checks. Correct units never change, so correct text stays clean (the 13 correct sentences pass).
- **Refactor:** `syllablesByPlain` (cached per syllable list) and `accentCombinations` in `text.ts`, shared by the checker and the dictionary; the dictionary's `lookup`, `checker` and `syllables` became local functions so `segment` and `variants` reuse them.
- **Tests** (65): fake data: the neighbor fix (and *nay* alone left alone), `segment` and `variants`; real data: *Hom nay toi di cho*, *Chung toi se di Ha Noi*, *Toi an com voi ma*, `segment` and `variants` (*muộn* → muốn, mượn, muôn).
- **Plain-letter runs** (2026-10-01, from Language Helper: *mua sam* wasn't fixed, since *sam* is a real syllable): in the neighbor pass, plain-letter syllables that aren't doubtful may vary too: any of them when the whole run has no accents (*nha bang* → *nhà băng*, *nha hang* → *nhà hàng*: probably typed without accents), and otherwise only those less common than `PLAIN_RUN_MAX_ZIPF` (5: *sam* 4.5 may; *sau* 6.5 next to accented *tháng* doesn't); a run with no doubtful syllable is fixed only when one headword wins by `PLAIN_RUN_MARGIN` (0.5 Zipf; *ban an* → *bản án* / *bàn ăn* tie, left alone). Accented syllables never change unless doubtful. *mua sam* → *mua sắm*, *nha sach* → *nhà sách*, *nha bang* → *nhà băng*; *nha tho* (*nhà thơ* 4.4 / *nhà thờ* 4.1 / *nhà thổ* 4.1) and *tháng sau* (a correct sentence that "June", *tháng sáu*, would have broken) and *cho con* stay. Tests: 65/65.
- **Not done:** neighbors only help when the run is a headword: *đi chợ* isn't, so *di cho* is still fixed syllable by syllable (*đi* · *cho*, since *cho* is a common word). Two-word phrases from sentence frames or bigram frequencies could decide more.

## Letter typos (2026-10-02)

The owner asked for standard spellchecking beyond accents ("option 1"): misspellings that aren't accent-related.

- **`spellingCandidates(written, syllables, byPlain, { limit, minZipf = 3, similar })`** (`text.ts`): the written syllable's plain letters, every one-letter change (delete, transpose, replace, insert over a–z), each mapped through `byPlain` to all its accent forms; same-letter accent forms are cost 0; letter changes 1, or 0.5 when replacing within a `similar` group; letter-changed syllables only at Zipf ≥ `minZipf`. Order: **tier 0** = same letters keeping every mark the writer typed (accents moved or added: *ngừoi* → *người*); then mark score (shared − missing − extra; 0 when the writer typed no marks, so plain writing isn't held against any candidate), then cost, then frequency. Returns `{ word, edits, marks }`.
- **Spelling rule:** non-syllables now get these candidates (top 3) instead of accent forms only. A plain-letter non-syllable with no accent form is treated as a typo only if a one-letter fix reaches Zipf ≥ `PLAIN_TYPO_MIN_ZIPF` (4) and it isn't a capitalized word mid-sentence (else a name or foreign word, as before). Letter typos don't count as missing-accents for the "typed without accents" mode. In neighbor runs, misspelled syllables use only their **best-ranked** candidates (ties on marks and cost): "muốm ăn" became "muối ăn" (table salt, a headword) through a worse fix than *muốn*. Skipped entirely now: units with a capital after the first letter (abbreviations, *GĐ*, *TKiều*) and units with letters outside the language's alphabet (from its syllables; Chinese characters got "→ ở").
- **`CheckerConfig.similarLetters`** (vi: `['ckq', 'sx', 'iy', 'mn']`): *họk* → *học* before *họ*.
- **Results:** khôg, khôngg → không; họk → học; tihch → thích; muốm → muốn; Cảm ơm → Cảm ơn; ngừoi → người. Not caught (real syllables): *kông* (a syllable at Zipf 4.3), *mún*, *bít*, and texting forms (*ko*, *dc*, *j*): option 2, a per-language shorthand list, not built.

## Place names (2026-10-02)

The owner found "nhat"/Nhật didn't translate to Japan. Audit: no country translated English → Vietnamese, and most Vietnamese → English gave the adjective or a homonym (*Pháp* → rule, *Ý* → idea). Two build rules caused it: Vietnamese `name` entries were left out of the English index (`NOT_IN_ENGLISH_INDEX`), and English skipped `name` entirely (`skipPos`), so there was no English "Japan" (only *japan* the varnish).

- **`LanguageConfig.placeNames?: { minZipf? }`** (vi `{}`, en `{ minZipf: 3 }`). A `name` entry is a place when any of its senses has a Wiktionary category of `kind: 'place'` (country when a category is "Countries…" or has parent "Countries"). Categories are read **per entry**, because Kaikki attaches page categories to whichever sense (*Nhật*'s "Countries in Asia" is on its given-name sense). A place entry's **place senses** are its senses whose first gloss isn't a personal name (`PERSONAL_NAME`: given name, surname, family name, patronymic, nickname). Build-time `WeakMap`/`WeakSet` (`PLACE_ENTRIES`, `PLACE_ONLY`), nothing new stored.
- **English index:** a `name` entry's place senses are indexed (still nothing else of names). Vietnamese: 1,056 place names (370 countries); 30,111 English terms (was 29,442).
- **English data (`skipPos` has `name`):** names are kept only as places, with only their place senses, and non-country places only when Zipf ≥ 3 **and** not also an ordinary English word (otherwise they borrow its frequency and take over its capitalized form: *Well*, a village, made "Well, …" translate as *giếng*; also *Reading*, *Bath*, *Nice*). 4,537 places, 325 countries; 599,081 entries (was 594,544). `keepWord` (≤ 2 words) still applies, so "United States of America" isn't kept, "United States" is.
- **Translator:**
  - An English `name` sense bridges by its own name only (`bridgeTerms`). Its definition ("A country in East Asia. Capital and largest city: Tokyo.") would find Tokyo.
  - For English place names, a target hit counts only if its gloss is of the place (`namesPlace`): it starts with the name (notes aside), or is a short term list including it ("Nhật": "Japano-; Nippo-; Japan"), or the hit is a spelling variant. `hit.primary` wasn't enough: `glossTerms` skips long parts without counting them, so "Japan" was the *first* term of *hoàng bào*'s "yellow court robe … of imperial China, Japan, Korea and Vietnam", and "Vietnam" of *Vinh*'s "the provincial capital of Nghệ An Province, Vietnam".
  - `englishCandidates` also looks up the title-cased term ("south korea" → "South Korea", not only "South korea").
- **`withoutNotes`** (types.ts, used by `glossTerms`): removes nested parentheses and a note left open by a cut-off gloss. *Hàn Quốc*'s "South Korea (a country …; official name: Đại Hàn Dân Quốc (“Republic of Korea”))" gave no term before (the single-pass regex left "official name: …", and the colon rule kept only that).

One new unhelpful flag: *Hughes* (a person; also an Australian place) is read as English with no translation, so the journal review lists it as unchecked.

## Pronoun table (added 2026-09-30)

Vietnamese pronouns depend on the relationship (*con* = I, to a parent; *anh* = you, an older man), so the translator can't pick one from "I" alone (it ranked *tôi* 27th). The owner asked for a "who are you talking to? / you say I / you call them you" chart. Decided with the owner: store the **chart itself** keyed by relationship, not per-word tags, because pairs go together (*tao*/*mày*), some choices depend on the speaker's gender, and warnings belong to the situation.

- **Config:** `LanguageConfig.address`: rows `{ id, label, self, addressee, warning? }`. Each cell pick is either `{ word, gloss: RegExp, speaker? }`, a pronoun sense of that word whose definition matches (region, labels and the definition come from the sense), or an **override** `{ word, regions?, labels?, speaker?, note }` for what no definition says. Vietnamese definitions follow "I/me, your X" / "you, my X", so most cells come from them.
- **Build** (`scripts/pronouns.ts`, called from build-language.ts): writes `data/pronouns.json` (`StoredPronounRow[]`, stored-form choices) and sets `meta.pronouns: true`. Prints counts and **warns for picks that no longer match** a definition (Wiktionary rewording after a refresh). Build of 2026-09-30: 11 rows, 38 words from definitions, 6 overrides, 5.7 kB.
- **Vietnamese overrides** (the gaps in the definitions): *em* as "I" (older man/woman, teacher, partner): Wiktionary only says "refers to any person described by the noun em"; *ba*/*má* (Southern parents): no pronoun sense at all. Picks worth knowing: *tui* comes from its "alternative form of tôi" sense (Central/Southern); *thầy* "you, my father" is dated, so it's hidden by default.
- **API:** `dictionary.pronouns({ listener?, region?, speaker?, exclude? })` → `PronounRow[]` (`PronounChoice`: word, gloss?, source 'gloss' | 'override', regions, regionTagged, labels, speaker?, note?). `region` accepts groups (untagged = every region); `speaker` drops the other gender's choices; `exclude` defaults to `DEFAULT_EXCLUDED_LABELS`; an unknown `listener` throws, listing the ids. Languages without a table return `[]` (no request is made).
- **Renamed** from "address table" to **pronoun table** at the owner's request, the same day, before publishing: `dictionary.pronouns()`, `pronouns.json`, `meta.pronouns`, `LanguageConfig.pronouns`, `PronounRow`/`PronounChoice`, `scripts/pronouns.ts`. Rows keep `self`/`addressee` (the "I" and "you" sides).
- **In the translator** (`listener?`, `speaker?` options): `personOf(sense)` marks singular "I"/"you" **pronoun** senses from their definition (`FIRST_PERSON`: starts "I"/"me", "the speaker", "first-person singular"; `SECOND_PERSON`: starts "you", "spoken/written to", "person addressed", "second-person singular"; plural "people"/"we"/"you all" excluded — the table is singular). When the target has a table and a sense has a person, the rows are loaded once (filtered by `toRegion`, `speaker`, `exclude`) and the group gets `relationships` (`RelationshipWords[]`: id, label, words, warning). With `listener`, that row's words go first (score = best score + 1, table order kept by +0.1 steps), `bridge: 'pronouns'`, `relationship` = the row label; the dictionary's words follow. A listener also ranks person senses first (+20 relevance): Wiktionary lists plural "you" first. Unknown listener throws (via `pronouns({ listener })`); targets without a table ignore it. Examples: I → parent *con*; you → parent, Southern *ba*, *má*, *mẹ*; I → younger, female speaker *chị*; me → teacher *em*; you → close friend *mày*.
- **Design change from the plan:** relationship words are **not** moved out of `translations` when there's no listener: every word, including *tôi* and *mình*, is in some row, and after the ranking fixes the general words already lead. `relationships` gives apps the per-relationship list instead.
- **Reverse direction** (source language has a table; skipped when `pos` isn't 'pron'): `pronounUses(rows, word)` finds the source word's choices, filtered by `fromRegion`, `speaker`, `exclude`. Each use goes on the groups whose source glosses include the choice's `gloss` (a person sense from that definition: *con* "used by children when talking to their parents" → `parent`); uses without a home (overrides, or definitions whose sense had no translations) become **one synthetic group per person**: pos 'pron', gloss "I/me, when talking to: …" / "you, when talking to: …" (labels lowercased, "(said by a man/woman)" for speaker-specific), regions = union when all uses are tagged, `bridge: []`. Its translations (`pronounTranslations`): into English, `englishCandidates` for I/me or you (bridge 'pronouns'); otherwise the translator's own English "I"/"you" → target (passing listener/speaker/register), keeping only pronouns when there are any (English "I" also finds letter names). Synthetic groups come after the dictionary's senses (dictionary order rule); `pos: 'pron'` returns only pronoun senses. The translator object is now `api` so it can call itself (English has no pronoun table, so no loop). Examples: *em* → en "I, me" (older-male, older-female, teacher, partner — all overrides) and "you" (younger, partner); *ba* → "you" (parent); *em* vi → vi with `listener: 'parent'` → *con*.
- **English case fix** (`englishCandidates`): terms are lowercase, so the capitalized word is looked up too, and when an entry with the exact source POS is usable the other compatible POS are dropped. Into English "I" was coming out as the letter *i* (noun, compatible with pron).
- **Third person and plurals (2026-09-30, owner's request to fix English → Vietnamese pronouns).** Rows now have six columns (`PRONOUN_PERSONS`): `self`, `addressee`, `third` (he/she), `selfPlural` (we), `addresseePlural`, `thirdPlural` (they); stored rows omit empty ones. Choices can carry `gender` (of the person referred to: *anh ấy* male, *chị ấy* female) and `inclusive` (for "we": *chúng ta* true, *chúng tôi* false). A third pick kind, **rule** (`source: 'rule'`), is for regular compounds the dictionary doesn't list, with a note naming the rule; vi.ts builds them with helpers `cac` (các + X: plural you/they), `chung` (chúng + X: we, exclusive), `tui_` (Southern tụi + X) and `ay` (X + ấy: he/she). The build warns if a rule's word is in the dictionary (use its definition instead) and if more than one row is `default`.
  - Dictionary facts worth knowing: *anh ấy*, *chị ấy*, *ông ấy*, *bà ấy*, *cô ấy* are tagged **Northern** in Wiktionary; the Southern forms *ảnh*, *chỉ*, *ổng*, *bả*, *cổ* have their own definitions, so a Southern region filter swaps them. *chúng tôi*/*chúng ta* (exclusive/inclusive), *chúng mình*, *tụi tui* (S), *chúng mày*, *bây*, *chúng nó* (N), *tụi nó* (S), *họ*, *mọi người* ("you guys"), *quý vị* are defined; *các X*, *chúng em/con/cháu*, *tụi em/con/mày/tao/mình*, *em ấy*, *bạn ấy*, *cậu ấy*, *chú ấy* are rules. *chúng tao* is labelled vulgar, so it's hidden by default.
  - New **`general` row** (`default: true`, "Anyone / not sure (neutral)"): tôi, mình, tui / bạn, anh, chị / anh ấy, chị ấy, ảnh, chỉ, nó / chúng tôi, chúng ta, chúng mình, tụi tui / các bạn, mọi người / họ, chúng nó, tụi nó. Build of 2026-09-30: 12 rows, 95 words from definitions, 37 from rules, 10 overrides, ~20 kB.
  - **Translator:** `personOf(sense, from)` returns `{ person, gender?, inclusive? }`. English is by the **word** (`ENGLISH_PERSONS`: I/me, you, he/him, she/her, we/us, they/them, y'all…), because English object pronouns are defined by grammar ("him": "With dative effect…"); plural "you" by "people/yourselves/plural", singular "they" by "One …", and not-a-person senses (`NOT_A_PERSON`: "It; an animal…", "A ship", "Anyone") excluded; inclusive/exclusive from the definition. Other languages by the definition's start (I/me, we/us (+ inclusive/exclusive), you … plural/guys, they/them, you, he/him, she/her). New option **`about`** picks the row for third/thirdPlural (`ABOUT_PERSONS`); `listener` the rest; without one, the **default row** — but only for plain senses: a definition naming a relationship (`RELATIONAL`: your/my, "used by/when/to", "talking to", "toward") gets no default (*bố* "I/me, your father" N→S must stay *ba*, not *tôi*). Row words are filtered by `fits()` (gender, inclusiveness), then ordered target-region-tagged first, then `registerFit`, then table order. Group relevance: +10 when the relevant option is given; −3 for plural person groups only when the word also has singular person groups (plural "you" is Wiktionary's first sense; lowering all plurals put "we" the determiner above "we" the pronoun; raising singulars put *bố*'s pronoun senses above "father"). The reverse direction handles all six columns (synthetic gloss "he/she, when talking about: …", English words by column and gender).
  - **Results:** I → tôi, mình, tui; you → bạn, anh, chị; he → anh ấy, ảnh, nó; she → chị ấy, chỉ, nó; we → chúng tôi, chúng ta; they → họ, chúng nó, tụi nó; y'all → các bạn, mọi người; Southern he → ảnh, we → tụi tui, they → tụi nó; we to a parent → chúng con; he about a grandparent (S) → ổng; she about a teacher → cô. Evaluation: tuning 82/84 (5 new pronoun cases, all first), held-out unchanged 30/30.
- **Known gaps:** plain "her" leads with its possessive (determiner) sense, which the table doesn't cover (Vietnamese possessives are "của" + pronoun); capitalized honorifics (*Người* for "him") still appear after the table's words.

## Known limitations / tuning notes

- Without `pos`/`meaning`, the first sense follows the dictionary's order, which isn't frequency (e.g. *just* the adjective "fair" before the adverb; *tôi* the noun "servant" before the pronoun). Callers should pass context.
- Non-English → non-English goes through English definitions, so distinctions English doesn't make can be lost.
- Grammar words defined by function ("marks the future tense" for *sẽ*) aren't reachable from English *will*; *will* → *biết*. *gonna*, *would*, *wanna*, *didnt* still return nothing.

- No frequency data; `senses` is a proxy and sometimes wrong (e.g. "wait" ranks rare *dàng* first; "mother" ranks *mẫu* above *mẹ*).
- `searchEnglish` ranks region-tagged words above untagged ones when a region is given, so region searches surface regional/kinship words first. Intentional for dialect learning, but not "most common first"; the translator's scoring (tables, frequency) corrects this for "I" (Southern → tui, mình, tôi, tao, ta since 2026-09-30).
- Capitalized duplicates (Mẹ/mẹ) appear as separate words.
- Glosses with no plain term ("thank you" is glossed "to thank") or grammar words ("the") return nothing.
- The real-data tests assert specific results (vi: hông, lợn/heo, chừ, má, pronouns; en: truck → lorry) and may need updating after a Kaikki refresh if Wiktionary changes. Real-data suites skip when that language isn't built.

## Working conventions

- **Design every improvement and feature to scale to more languages** (owner's rule, 2026-09-30). Vietnamese and English are the first of many. Before adding something, check: does it work, or degrade gracefully, for a language that doesn't have it yet? Is per-language work kept in `languages/<lang>.ts` and that language's data package, not in the API or in language-pair code? Does the work grow with the number of languages (fine), not with the number of pairs (English is the bridge)? Is it measured per language? Rules that only hold for one language's data (Vietnamese glosses, English grammar words) go in that language's config or behind a language check, and say so in a comment. Example: the planned picks layer (FUTURE_IMPROVEMENTS.md).
- Keep code MIT and data CC BY-SA; keep attribution in READMEs and `packages/<lang>/LICENSE`.
- `npm test` and `npm run typecheck` clean before committing.
- Never commit generated data or `.cache/`.
- Update this file after major changes.
